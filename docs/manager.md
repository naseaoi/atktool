# 设备管理页

## 窗口高度

- 窗口创建时保持隐藏，前端同步测量 `.app-shell` 加 body 内边距后调用 `fit_manager_height`，设好高度再显示，避免先以默认高度出现再跳动。前端 1.5 秒内没有上报时由 Rust 兜底显示。
- 首次测量必须同步执行：隐藏窗口中的页面定时器会被节流，延迟测量会拖慢窗口出现。
- 高度上限为当前屏幕工作区剩余高度，下限为 `window_manager::MANAGER_MIN_HEIGHT`。前端按高度去重，只有内容高度真正变化（首次显示、窗口变窄导致换行）时才上报。
- 页面各状态的布局高度保持一致，操作过程中窗口不应变高变矮：状态说明固定占设备卡续航行的两行位置，设置保存错误以浮层显示、不参与布局。版本页脚始终占一行固定高度，检查状态与更新按钮在行内切换。
- 截图脚本的 `MANAGER_HEIGHT` 要与实际内容高度一致，否则截图底部会留白或被裁切。

打开项目主页与发布页的命令只接受本地窗口调用，目标由后端确定；发布链接仅信任固定仓库的 `releases/` 路径。

## 状态呈现

- 设备卡复用悬浮窗的视觉语义（中性表面、电量色阶、状态胶囊），电量判定来自共享的 `battery-view.js`。
- 续航行在线时显示续航估算，离线时显示“最后读数时间 · 后端 `message`”，超出两行截断并在悬停提示中给出全文。
- 设置项点击后立即调用后端，控件状态以回推的偏好事件为准；保存失败时恢复为当前偏好并显示错误浮层。
