# 悬浮窗

## 窗口尺寸

- 窗口实际尺寸由前端决定：`overlay.js` 测量 `.panel`（卡片外加 8px 阴影留白，已含尺寸档位的 `zoom`），通过 `fit_overlay_size` 上报。Rust 侧 `overlay_geometry` 只给出创建窗口时的初始尺寸，改布局时两边要同步，否则首帧会闪动。
- 卡片底色保持不透明。半透明底色会透出背后窗口的文字，透明度只通过“不透明度”偏好作用在整张卡片上。
- 窗口矩形包含 8px 透明留白，贴边判定、吸附和隐藏后保留的细边宽度都按窗口矩形计算，视觉上卡片离屏幕边缘有 8px。

## 拖动与双击

- 必须在 `mousedown` 时立即调用 `startDragging`。按下后再按位移阈值延迟发起时，WebView2 已经接管这次指针序列，系统拖动会立刻结束。
- 系统拖动会吞掉 `mouseup`，页面收不到可靠的 `click`/`dblclick`，因此双击用第二次按下的 `event.detail === 2` 识别。
- 位置只在拖动结束（`WM_EXITSIZEMOVE`）和非动画移动时保存，由 `overlay_edge.rs` 的窗口子类负责。贴边隐藏的滑动坐标不写入偏好。

## 贴边吸附与自动隐藏

- 吸附在 `WM_EXITSIZEMOVE` 时以窗口所在显示器的工作区计算：任意边距离在 ±16 逻辑像素内吸附；越过左、右、上边缘时拉回贴边。底边只做近距离吸附，越过底边通常是在拖向任务栏。
- 越界拉回前用 `MonitorFromRect` 探测屏幕外侧是否有相邻显示器，有则视为跨屏移动、不拉回。探测基于物理屏幕边缘（`rcMonitor`），工作区边缘可能隔着任务栏。
- 只有贴住且外侧没有相邻显示器的边才会自动隐藏，同一时刻只沿一条边隐藏。
- 滑动动画由 `overlay-vsync` 工作线程调用 `DwmFlush` 等待合成器刷新，再向窗口投递帧消息；窗口线程按实际经过时间采样 150ms 三次缓出曲线。帧率因此跟随显示器刷新率，掉帧时也不会变慢。线程只允许一帧在途，DWM 不可用时退回 1ms 定时器。
- 动画中途指针返回时，从最后绘制的位置反向滑回。拖动和打开菜单会立即中止动画并滑回原位。

## 状态与可见性

- 所有采样结果都经过 `AppState::replace_overlay`：它负责记录最后电量、续航估算、低电量通知和派生字段 `OverlayView`。调用方要广播它的返回值。
- 电量阈值（20% 低、10% 极低）与续航文案在 `battery-view.js`，悬浮窗和管理页共用；低电量通知（`battery_trend.rs`）、智能显示（`overlay_behavior.rs`）和低电量轮询（`battery_service.rs`）各自在 Rust 侧写有同样的阈值，改动时保持一致。
- 全屏隐藏和智能显示只临时隐藏窗口（`window.hide`），不修改 `overlay_visible` 偏好。用户主动隐藏才销毁窗口并写入偏好。
- 临时隐藏期间用户从托盘手动显示，会一直保持到“需要关注”状态（低电量或充电）下一次变化。
- 原生右键菜单的事件 ID 以 `overlay.` 开头，由托盘的全局菜单监听器（`system_tray::handle_menu`）分发。
